# AI import (2026-11-17)

Based on `feature/2026-11-17-padsync-context-control`, which already carries the merged bridge
work (#1). Reuses its job file bundle and per-job temp dir; nothing here adds a second way of
getting files to the agent.

## Current flow (before this change)

Two separate pages:

1. **AI prompt** (`/prompt`, `PromptView`): pick one of three presets or type a request; the page
   shows `buildPrompt(request)` (format description + example) and a *Copy prompt* button. The
   user pastes that into Claude/ChatGPT **by hand**, attaches the lecture files there, waits, and
   copies the reply.
2. **Import** (`/import`, `ImportView`): paste the reply or drop a `.json`; `parsePayload` strips
   code fences, `payloadSchema` (zod, `padsync: 1`) validates, *Create notebook* calls
   `createNotebook`.

The Mac bridge (Ask AI) already writes job files into a 0700 `padsync-job-*` dir, lets the agent
write to `out/` and returns those files, but import never used it.

## Problems

- Two pages, and the round trip between them goes through someone else's chat window. Nothing
  connects the prompt that was sent to the reply that comes back.
- Lecture notes can't be attached in padSync at all, so the bridge can't be used for import.
- The format only describes practice problems: markdown, code, image, space, divider. No way to
  express explanations, worked examples, derivations, concept maps, glossaries, note skeletons with
  blanks, annotation margins, recall questions or checkpoints, so the AI flattens everything into
  markdown and answer space.
- Validation is all or nothing: one bad block rejects the whole file. Error paths read
  `sections.3.blocks.1.text: Invalid input`. Unknown fields are silently dropped, unknown block
  types are fatal, and `padsync: 1` is the only accepted version, with no way to migrate.
- Paste state is lost when you leave the page. Clicking *Create notebook* twice creates two
  notebooks, and importing the same reply again gives no warning.
- Job bodies are capped at 3.2 MB (Vercel's 4.5 MB request limit), which is smaller than many
  lecture PDFs.

## New design

### One tab: AI import (`/import`)

`/prompt` redirects to `/import` (next.config `redirects`), and the Library shows one **AI import**
link. The page is a single column of numbered steps, each always visible:

1. **Lecture notes**: drop zone and file picker (PDF, PNG/JPEG/GIF/WebP, other images converted
   to JPEG, Markdown/text/LaTeX/CSV, PPTX/DOCX). The list can be reordered (drag, or ↑/↓) and items
   removed, and it shows size, kind and per-file errors. Attachments are kept in IndexedDB
   (`padsync-drafts`), so leaving the page or reloading doesn't lose them.
2. **What to make**: *goals* (multi-select: practice problems, explanations and worked examples,
   concept map and summary, glossary and mnemonics, note skeleton with blanks, margins and
   annotation prompts, recall questions and checkpoints, timed test) plus a free-text request.
   Agent, model, effort, web search and *allow running code* (for slides) sit in the same box.
3. **Generate**:
   - **Send to Mac bridge** (when signed in; the status dot shows whether the bridge is online).
     Progress goes uploading (bytes) → waiting for bridge → running (streamed tail) → done. *Cancel*
     works at every stage. Errors are shown in place with a retry.
   - **Fallback, no bridge**: *Copy prompt* / *Download prompt*, with a reminder to attach the same
     files in the chat. Then paste the reply in step 4.
4. **Review**: one parser for every source (bridge result, pasted text, dropped `.json`). Shows
   the title, a section list with kind badges and block counts, warnings (unknown fields, migrated
   version, coerced values), and errors per section with the exact path. Sections can be unticked.
   If some sections are invalid, the button reads *Import 9 of 10 sections*: a partial import has
   to be chosen explicitly, never happens silently. *Edit JSON* opens the raw text.
5. **Import**: creates the notebook in one `putEntities` call (one IndexedDB transaction), stores
   `source.importHash` on the notebook, and disables itself while running. Importing a payload
   whose hash is already in the library asks first and links to the existing notebook.

The flow logic (stage, which result file to use, request body, duplicate check) lives in pure
modules (`src/lib/ai-import.ts`, `src/lib/attachments.ts`), so it is tested without a browser.

### Sending attachments through the bridge

Same mechanism as Ask AI: the job carries files, the bridge writes them into the per-job temp dir
with `prepareJobDir`/`withJobDir`, and the prompt names absolute paths, never content. Two
additions:

- **Job kind.** `jobs.kind` is `ask` (default) or `import`. An import job has no notebook. The
  bridge uses `buildImportPrompt` for it, always allows writing to `out/` (where the result goes),
  and gives it a 30-minute timeout.
- **Chunked inputs for large files.** Small files (`INSTRUCTIONS.md`, `request.md`) travel inline
  as before. Lecture files are declared in `uploads: [{path, mime, size, parts}]`, and the job
  starts in status `uploading`. The client PUTs base64 parts (≤ 2.4 M chars each) to
  `/api/jobs/:id/inputs`. The insert that completes the manifest flips the job to `queued` in the
  same statement. The bridge's claim returns the manifest, and it fetches each part with
  `GET /api/bridge/jobs/:id/inputs?path=&part=` (claiming device only, job running). It assembles
  them into ordinary `files` and hands them to the unchanged `withJobDir`. Limits: 25 MB per file,
  40 MB per import (raw). Parts are deleted when the job finishes, errors or is cancelled, and
  imports stuck in `uploading` for more than a day are cancelled at migrate.
- **File names.** The client never uses the user's file name as a path: each attachment becomes
  `lectures/NN-<ascii slug>.<known ext>`, which matches `BUNDLE_PATH_RE` and is checked again on
  the server and by `safeJoin` in the bridge. The original name is only listed in `request.md`.
- **Result.** The agent writes `out/padsync.json` and optional figures to `out/figures/`. Image
  blocks may reference `figures/x.png`, which is resolved to a data URL from the returned files at
  import. If no JSON file comes back, the answer text is parsed instead (fences tolerated).

### Schema v2

```
Payload = {
  schemaVersion: 2,            // v1 files use "padsync": 1 and still import (migrated)
  title: string, description?: string, subject?: string,
  purpose?: "practice" | "understand" | "annotate" | "review" | "mixed",
  sections: Section[]
}
Section = {
  title?, kind?: "problem" | "explanation" | "worked-example" | "notes" | "summary" | "review" | "reference",
  objectives?: string[],       // "By the end you can…", shown under the title
  blocks: Block[],
  solution?, marks?, timeLimitMinutes?, tags?, template?,
  margin?: { side?: "right" | "left", width?: 0.15–0.45, prompts?: string[] }   // annotation column
}
Block = v1 blocks (markdown, code, image, space, divider)
  | callout    { style: definition|theorem|key-idea|intuition|example|warning|tip|mnemonic|summary|note, title?, text }
  | steps      { style?: derivation|worked-example|procedure, title?, problem?, steps: [{ text, why? }], result?, blankWhy? }
  | glossary   { title?, terms: [{ term, definition, example? }], hideDefinitions? }
  | conceptMap { title?, nodes: [{ id, label, note? }], links: [{ from, to, label? }] }
  | cloze      { text: "… {{answer}} …", hint? }                 // blanks, answers hidden until revealed
  | recall     { title?, items: [{ q, a?, space? }] }             // answers hidden, space to write
  | rewrite    { prompt?, text, space? }                          // "say it in your own words", lined space
  | prompt     { text, space? }                                   // annotation cue + space
  | checkpoint { title?, items: string[], space? }                // self-check list with tick boxes
```

Rendering: new blocks render natively in `SectionView` (callout boxes, numbered steps, a glossary
table, concept map cards and arrows, blanks drawn as writing lines, lined rewrite areas). Hidden
answers (cloze, recall, `blankWhy`, `hideDefinitions`) have a small **Show** chip above the ink
layer. They are hidden in renders until revealed, and the Ask AI bundle exports them as hidden
reference material. A margin narrows the content column and draws a ruled annotation column
with the prompts.

Compatibility and tolerance (`src/lib/schema.ts`):

- **Versions.** `schemaVersion` (or the legacy `padsync`) picks a migration chain:
  `MIGRATIONS[1]` lifts v1 to v2. A file without a version is treated as v2 with a warning. A
  newer version is parsed best-effort as v2 with a warning.
- **Unknown fields** are dropped with a warning naming the path (found by a second, strict
  parse). **Unknown block types** become markdown if they carry text, otherwise they are dropped,
  with a warning either way. Common AI spellings are accepted (`text`/`md` → markdown,
  `fill-in-the-blank` → cloze, `worked-example`/`derivation` → steps, `concept-map` → conceptMap,
  size words like `"large"`), and out-of-range numbers are clamped with a warning.
- **Errors** are reported per section, with readable paths such as
  `sections[3] "Q4" › blocks[1] (cloze) › text: required (text)`. A bad section is excluded,
  never half-imported.
- Limits: 8 MB of JSON text, 500 sections, 500 blocks per section.

The prompt sent to the AI (`buildPrompt`, also written as `INSTRUCTIONS.md`) describes the v2
schema, says when to use each block for each goal, and gives an example payload that the tests
validate.

### Out of scope

- Server-side PDF parsing or OCR: the agent reads the files with its own tools (Claude's Read
  handles PDFs and images; Codex is told to extract text with a command if needed).
- Re-asking for changes to the same import: refine with *Edit JSON*, or send again with a new
  request.
