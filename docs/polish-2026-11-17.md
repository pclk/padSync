# padSync polish — 2026-11-17

## Inspection and scope

Read AGENTS.md and the installed Next 16.4.6 guides for lazy loading and Link before editing. Installed the locked dependencies with npm ci. Inspected the running library in the shared preview at 1280 × 800, then tested at 390 × 844. Created a local notebook and opened the editor. This pass focuses on finding and managing notebooks; no schema or sync protocol changes.

## Suggestions applied

- **Find notebooks by title and choose their order.** Added literal, case-insensitive search, newest/oldest/title sorting, result counts and a clear-search recovery state. Sorting copies data and uses IDs to break ties. The iPad shortcut searches the full library so filtering cannot hide its destination.
- **Make notebook management usable on touch and keyboard.** Rename/Delete now remain visible in each card, have notebook-specific accessible names and retain deletion confirmation. Cards use one column on narrow screens and expand to two/three columns. Header navigation wraps. Long titles have a native tooltip.
- **Explain loading and empty states.** Loading local data is announced separately from an empty library; the library has a clear heading and brief purpose statement. Section counts show an ellipsis while unresolved and use singular/plural labels.
- **Handle unsuccessful writes.** Creation, rename and deletion share a guarded pending state. Repeated clicks cannot enqueue simultaneous writes, controls disable during saves, and a failed write exposes a retry message. The next action clears that message.
- **Expose sync status to assistive technology.** The compact badge now has a useful accessible name even when its text is hidden at smaller widths. Added visible keyboard focus outlines to interactive chrome.

## Suggestions skipped

- Custom rename/delete dialogs and undo deletion: worthwhile follow-up, but require deliberate focus management and deletion semantics. Native prompt/confirmation remain for this pass.
- Last-edited sorting: notebook createdAt is available, but a trustworthy last-edited timestamp would require a separate data decision across synced entities. The UI explicitly says newest/oldest rather than implying recent activity.
- Ink editor redesign, PDF preview and import flow changes: larger workflows with existing specialist controls; changing them would dilute this focused library pass.
- Framework/dependency upgrades: outside this UI change. npm ci reported seven moderate audit findings; the lockfile was left unchanged.

## Independent second opinion

Reviewed the complete uncommitted implementation, surrounding store/sync paths, CSS and the validation claims. Read the installed Next Link reference before editing. No additional agents were used.

Findings fixed:

- **Save recovery could duplicate notebooks (medium).** `createNotebook` persisted its content before writing its event. If event storage failed, the new error handler reported failure while leaving a notebook behind. Wrapped content and event writes in one IndexedDB transaction so a failed creation can safely be retried. Added real fake-indexeddb tests for event-write rollback and retry, content-write failure, and successful multi-section creation including dirty flags and event metadata.
- **Clear search discarded keyboard focus (low).** Its button unmounts when results return. It now focuses the search input when clearing the query.
- **Long iPad shortcut titles could overflow (low).** The shortcut text now has a shrinkable, wrapping container.

Added five independent rendering cases for unresolved counts, section pluralization, hostile title escaping, missing/deleted presence destinations and live iPad destinations. These supplement the existing selection and rendering tests; they do not simulate browser interaction.

Review limits and follow-ups:

- This second pass used source review and automated checks; the browser observations above belong to the initial implementation pass. Keyboard focus and long-title fixes have not received a new browser/manual screen-reader check.
- Real cloud sync and multi-device conflict behavior remain unverified without configured services. Existing entity-level last-write-wins rename/delete behavior and native dialogs remain unchanged.
- Native title tooltips are useful for mouse users; a future expanded title treatment could improve reading long names on touch screens. A separate local-read failure recovery state would also improve resilience beyond the current loading/write-error states.

Final independent validation: `npm test` passed **30 files / 421 tests** (eight additional cases); `npm run typecheck`, `npm run lint`, `npm run build`, and `git diff --check` all passed.
