## Pencil writing on iPad (top priority)

0a. ~~**Pencil sometimes freezes and stops taking input**~~ ✅ done 2026-11-18 (01:45 run).
    Root causes found and fixed:
    - **Stuck gesture (main cause).** `InkController.down()` returned early while `this.gesture`
      was set, and `move`/`up` only listened to that gesture's `pointerId`. One lost
      `pointerup`/`pointercancel` (capture lost, Scribble, an edge swipe or app switch, a section
      unmounting mid-stroke) left the gesture open forever, so every later Pencil touch was
      ignored, and two-finger pinch was disabled too (`!controller.isDrawing()`). Now a new
      pointerdown commits the stale gesture and starts fresh; `lostpointercapture`, a hover move
      with `buttons === 0` from the drawing pointer, window `blur`/`pagehide`/hidden visibility
      and SectionView unmount all end it (keeping what was drawn). `setPointerCapture` throwing
      for a pointer WebKit already dropped no longer aborts the stroke.
    - **Pen vs. scrolling.** The pan claim is avoided by the existing non-passive window
      `touchstart`/`touchmove` `preventDefault` for stylus touches on `.ink-surface` (confirmed;
      `touch-action` stays `pan-x pan-y` so fingers still scroll). A pen touch that lands during
      momentum scrolling can still get a `pointercancel` from WebKit (that touchstart is not
      cancelable) — it now commits and frees the pen instead of wedging.
      `.ink-surface` also sets `-webkit-touch-callout: none` and `-webkit-user-drag: none`.
    - **Main-thread work during writing.** Each stroke commit did an IndexedDB write, a second
      write for `logEvent`, an `emitActivity` that re-renders the whole editor (layout mode), and
      sync could start encoding/applying mid-stroke. `logEvent` and `emitActivity` for strokes and
      erases now run in `requestIdleCallback` (50 ms timeout fallback on Safari); background sync
      waits (250 ms steps, at most 3 s) while a gesture is open (`isInking()` in
      `src/lib/activity.ts`). Not measured on a device in this run — check with the sync debug panel.
    Tests: `tests/pencil-freeze.test.ts`.
0b. ~~**Pencil lines less smooth than the trackpad, and stray dots**~~ ✅ done 2026-11-18 (02:30 run).
    The mouse path uses simulated pressure, the pencil used raw `pressure` with `thinning: 0.55` and
    `streamline: 0.32` (`src/ink/render.ts`), so pressure noise showed as wobbly width; the first
    pencil samples have near-zero pressure; short taps or a resting/bouncing pencil committed as dots.
    - **Pressure filter, at render time** (`smoothPressure` in `src/ink/filters.ts`; stored points
      stay raw, so old strokes get the smoother look too and nothing is versioned). Samples below
      `PRESSURE_FLOOR` 0.05 (touchdown ~0, pointerup always 0) hold the previous value — leading
      ones take the first real pressure, so strokes no longer start with a hairline tail. Then an
      EMA (`PRESSURE_ALPHA` 0.2, ~20 ms at 240 Hz) with each step clamped to `PRESSURE_MAX_STEP`
      0.03 (a 0.5 press still lands in ~70 ms). The filter is causal, so a live prefix gets exactly
      the widths the committed stroke will have.
    - **Pen options** (pen input only; mouse/trackpad unchanged): `thinning` 0.55 → 0.5,
      `streamline` 0.32 → 0.45, `smoothing` 0.5 → 0.6. Before/after was compared by rendering a
      noisy synthetic 240 Hz cursive stroke to PNG; the new pen line is close to the mouse one.
    - **No jump on lift**: the live stroke used `last: false`, which in perfect-freehand leaves the
      streamlined end trailing behind the tip, then snapped forward at commit. It now renders with
      `last: true`, identical to the committed outline. Predicted events are capped at 2
      (`MAX_PREDICTED`) and carry the last real pressure (they used `pressure || 0.5`, which could
      fatten the tip). Coalesced events were already used. Note: tiles cap their scale at 2.95, so at
      high zoom the committed ink is slightly softer than the overlay — a resolution difference, not
      a shape change.
    - **Stray dots** (`isStrayDot`, checked in `commitInk`): a pen stroke is dropped only when all of
      its points lie within `DOT_MAX_EXTENT` 1.5 units of the first AND contact lasted under
      `DOT_MIN_MS` 45 ms AND peak pressure stayed under `DOT_MIN_PRESSURE` 0.2. Duration and peak
      pressure come from every event of the gesture, including duplicate-position moves that are
      not stored (a held i-dot used to look 0 ms long). Mouse clicks are never dropped. Thresholds
      are first guesses from typical Pencil timings — tune on the device if periods go missing or
      bounces still show.
    Tests: `tests/pencil-smoothing.test.ts`.

## Improvements

### UX and design
1. ~~**Custom rename/delete dialogs with undo**~~ ✅ done 2026-11-18 (03:15 run).
   `Dialog` (`src/components/Dialog.tsx`) is a modal form: focus starts on `[data-autofocus]`,
   Tab/Shift+Tab wrap inside (`dialogKey`), Esc or a backdrop click closes, Enter submits (Delete
   is focused, so Enter confirms), focus returns to the trigger. Rename and Delete dialogs and the
   "Undo" toast live in `Library.tsx`. The delete is **held back for `UNDO_MS` (6 s)** and only
   then written (`deferredAction` in `src/lib/deferred.ts`); the notebook is hidden meanwhile.
   This keeps undo purely local: the server sweeps stored PDFs as soon as a deleted notebook is
   pushed, so writing and then un-deleting would lose them. Leaving the library, `pagehide` or a
   second delete commits early. Sections were never marked deleted, so pages come back as they
   were. Caveat: a tab killed without `pagehide` inside the window keeps the notebook.
   Tests: `tests/library-dialogs.test.ts` (node environment, no DOM: pure helpers and markup).
2. ~~**Dark mode**~~ ✅ done 2026-11-18 (04:00 run).
   `src/app/globals.css` has semantic tokens (`--surface`, `--border*`, `--text*`, `--accent*`,
   shadow colours, prose colours) used by `.card`, `.btn*`, `.icon-btn`, `.field`, `.segmented`,
   `.switch`, `.dropzone` and the file button. `:root[data-theme="dark"]` gives dark values for
   them and **remaps the Tailwind palette** (slate inverted, `white` → dark surface, brand and the
   rose/emerald/amber/blue/sky/indigo/violet tints and text shades), so the utilities in the
   toolbar, side panel, chat and library follow without per-component `dark:` classes.
   `:root[data-theme="dark"] .paper` restores the light palette (Tailwind's defaults) inside a
   page, so paper, templates, study blocks and ink stay as drawn; the ink pipeline is untouched.
   New utilities: `text-on-accent` (white on brand/emerald/blue fills; `text-white` now follows
   the surface, which suits the inverted slate-900 pills), `bg-canvas` (editor desk),
   `bg-backdrop` (dialogs). Preference: `padsync.theme` (`"system" | "light" | "dark"`, default
   System) via `useThemePreference` in `src/lib/settings.ts` (now with generic
   `readSetting`/`writeSetting`/`useSetting`); Settings → Appearance has the segmented control.
   `themeScript` (`src/lib/theme.ts`) runs in `<head>` and sets `data-theme` before paint;
   `ThemeSync` follows later changes, other tabs and the OS appearance, and updates the
   `theme-color` metas. Not done: highlight.js code blocks keep the light GitHub theme (light
   boxes in a dark chat); `text-brand-600` icons are a little dim on dark. Not checked on a device.
   Tests: `tests/theme-setting.test.ts`.
