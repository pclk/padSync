# Sync timing and load

The sync engine now coalesces writes from the first trigger rather than restarting a trailing timer on every trigger. A later trigger cannot delay an existing deadline. This bounds continuous-writing delays while retaining batching. Requests remain serialized, writes arriving during a request get a follow-up, and queued changes retain the existing HLC acknowledgement protection. HTTP sync attempts time out after 15 seconds. Failed attempts back off from 2 to 60 seconds, including under continuing edits. Returning online or to a visible tab resets the retry deadline. Hidden tabs use the existing 15-second poll interval; visible tabs use 2 seconds. Polling deadlines can send writes before their debounce expires.

GitHub login `pclk` is the admin (case insensitive), based on the authenticated signed session, not client input. Only this admin can PUT the global debounce setting. Browser session, CSRF origin and bearer-token separation checks remain in force. Values are integer milliseconds from 100 through 10000; the default is 400. The setting persists in Postgres and applies to new clients within approximately a minute while online, via a separate configuration GET. No existing auth admission rules were broadened.

This is a scenario estimate, not server instrumentation. The model assumes immediate responses, continuous visibility/connectivity, no retries, no pagination, no manual requests and an initially empty queue. Real network/server duration adds to polling intervals; actual counts can differ in either direction with visibility changes or backlog. Up to about one extra configuration GET per minute per active tab and settings-page reads are disclosed separately. Percentages are relative to modeled sync HTTP requests for the observed tab, not CPU, query count, money, or total traffic. An idle sync executes one pull SQL statement; batches with changes/events execute additional write statements, so equal request counts need not mean equal database load. Values above the visible poll interval need not reduce requests further. A quiet sample cannot predict a future busy lecture.

## Further optimization options

1. Add server-side request duration, response bytes, query timing and rows-read/written instrumentation. Aggregate by operation without notebook contents. This supplies measured database/compute evidence before attempting cost estimates; timing alone still does not equal billed compute.
2. Use a small realtime change notification to wake pull requests, with slower polling as recovery. This can improve remote-edit latency and reduce empty pulls, but introduces connections, notification traffic and reconnect complexity. Measure on real two-device traces first.
3. Adapt idle polling to recent remote activity, retaining immediate local pushes and wake on visibility/online. This reduces quiet-tab traffic at the expense of remote edit detection latency. Avoid changing the poll interval implicitly with the admin debounce.
4. Coordinate visible tabs with BroadcastChannel or an elected leader. This can avoid duplicate empty polling on one device. Leadership failover and per-tab IndexedDB lifecycle need explicit tests.
5. Bound batches by encoded bytes as well as entity count. Large embedded images can exceed a body limit even below 100 entities; a separate binary asset model would reduce repeated entity transfer. This needs a storage contract change, not just a shorter timer.
6. Fix the existing server sequence commit-order gap before broad multi-user concurrency: concurrent transactions can allocate sequence numbers before commit, letting a cursor pass a late-committing row. Use a transactionally ordered change log or another proven cursor protocol; lowering debounce does not fix it.

No live production database was changed during development. Tests use PGlite and fake timers. Browser multi-device latency and actual cloud load still need measurement. Requested independent Work delegation was unavailable due to the provider's local shadow-home configuration, not a usage limit; no Personal fallback was used.
