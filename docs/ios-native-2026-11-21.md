# Native iPad app (2026-11-21)

A native padSync app for the 13" iPad Pro (M4, iPadOS 26.6) with Apple Pencil Pro, side-loaded
with a free Apple ID. The Mac side stays the web app.

## Decisions

| Question | Choice |
| --- | --- |
| How native | Hybrid: native notebook screen, web UI (WKWebView) for library, AI import, chat, settings |
| Why | Pencil latency/feel, Pencil Pro features (squeeze, barrel roll, hover), PWA reliability |
| Ink | PencilKit (`PKCanvasView`), strokes converted to and from `StrokeData` |
| Storage | Native SQLite (GRDB) entity store + Swift port of the sync client |
| Repo | `ios/` in this repo, project generated by XcodeGen |
| Target | iPadOS 26, landscape, iPad only |

## Free Apple ID limits

- Install from Xcode over USB or Wi-Fi. The provisioning profile **expires after 7 days**; run
  from Xcode again to refresh (data is kept). At most 3 side-loaded apps per device.
- No push notifications, iCloud/CloudKit, App Groups, Associated Domains or TestFlight.
  PencilKit, Pencil Pro interactions, Keychain, background fetch and file import all work.
- iPad: Settings → Privacy & Security → Developer Mode on; after the first install trust the
  developer under Settings → General → VPN & Device Management.

## Architecture

```
┌──────────── padSync.app ────────────┐
│ SwiftUI shell                        │
│  ├─ WebScreen (WKWebView)            │  library, import, chat, settings (PADSYNC_HOST, p.siew.dev)
│  │    └─ intercepts /notebook?id=…  ─┼─► NotebookScreen (native)
│  └─ NotebookScreen                   │    sections ▸ PKCanvasView + PDFKit page + text boxes
│ Store (GRDB/SQLite): entities, events, meta (cursor, device id)
│ SyncEngine: POST /api/sync — push dirty, pull since cursor, HLC; same contract as src/lib/sync.ts
└──────────────────────────────────────┘
```

- **Auth**: sign in with GitHub inside the WKWebView as today; the `padsync_session` cookie is
  copied from `WKHTTPCookieStore` to the URLSession the native sync uses.
- **Device id**: native strokes carry `input: "pen"`, `device` = the app's own device id, so the
  Mac sees the native app as one more device; presence is written with `deviceKind: "ipad"` so
  *follow iPad* keeps working.
- **Stroke conversion** (`PKStroke` ↔ `StrokeData`): section-local coordinates in CSS px (the
  13" landscape width is 1376 pt = `PAGE_WIDTH`, so 1:1). `pts` stride 6 =
  x, y, pressure (`force / maximumPossibleForce`), altitude, azimuth, t (ms from `t0`, from
  `PKStrokePoint.timeOffset`). Pen → `PKInkingTool(.pen)`, highlighter → `.marker`; width from
  `size`. Web strokes are rebuilt into `PKStroke`s for display and erase. PencilKit and
  perfect-freehand outlines look alike but not pixel-identical.
- **Pencil Pro**: squeeze shows the tool palette (`UIPencilInteraction`, configurable), barrel
  roll shapes the fountain/marker nib (PencilKit native), hover previews the nib, haptics on
  tool change.

## Phases

1. ✅ **Shell** (2026-11-21) — XcodeGen project, app icon, WKWebView on the production URL with a persistent
   data store, cookie hand-off, `/notebook` interception (stub screen). Build and side-load.
2. ✅ **Store + sync** (2026-11-21) — GRDB 7.12 (`ios/PadSync/Store/`): `entity`, `event` and
   `meta` tables mirroring Dexie, `data` kept as JSON so unknown fields survive native edits.
   `SyncEngine` ports src/lib/sync.ts: batches of 100 entities / 500 events, `more` paging,
   ack only rows not rewritten in flight, newest hlc wins, backoff from `/api/sync-config`,
   waits up to 3 s for an open stroke. Polls at the visible rate only while a notebook is open
   (the web screens sync themselves), wakes on foreground, network return and sign-in (cookie
   observer), and pushes once more when the app goes to the background. No Neon Realtime yet.
   Tests: `ios/PadSyncTests` (`xcodebuild test`). Checked on the device: the first sync pulled
   the whole account (~80k rows) into a ~130 MB database.
3. 🟡 **Native notebook** (3a done 2026-11-21: column, PencilKit, PDF, templates, presence; blocks,
   text box editing and section add/delete still to do) — continuous section scroll, PKCanvasView per visible section, templates,
   PDF backgrounds (PDFKit, bytes via `/api/pdfs`, cached on disk), text boxes, section growth,
   two/three-finger undo/redo, PKToolPicker + squeeze, presence.
4. **One source of truth** — until this phase the WKWebView screens keep their own Dexie copy
   and converge with the native store through the server (offline, the library won't see new
   native ink until both sync). Then expose the native store to the web layer through a
   `WKScriptMessageHandler` bridge so Dexie isn't needed in the app.
5. **Lasso + Ask AI, block rendering** (Markdown/LaTeX blocks, solutions), returned files.

## Notes from phase 3a

- **PencilKit widths aren't point sizes.** Measured in `RenderWidthTests`: pen, monoline and
  fountain pen draw `2·(size − 2)` pt, so a point size of 2 (the web's default pen is 2.2) is
  invisible; the marker draws `0.485·size`. `StrokeCodec.pointSize(forWidth:)` converts.
- **Stroke identity** on iPadOS 26 is creation date + point count + random seed (PKStroke.id
  needs iPadOS 27). Web strokes get a seed hashed from their id, so a rebuilt stroke keeps its key.
- **Native strokes keep their PencilKit original** (`pk`, base64 PKDrawing; `pkAt`, the first
  sample when saved) beside the usual samples, so they reopen exactly as drawn. The web lasso
  only translates `pts`, which the app applies to the original as a move.
- The eraser is whole-stroke only: strokes sync whole, and a pixel eraser masks part of one.
- A remote change to a section redraws its canvas, which clears PencilKit's undo for that section.

## Risks

- Section blocks are Markdown + KaTeX; rendering them natively is real work. Phase 3 renders
  them in a non-interactive web snapshot behind the canvas.
- Service workers in WKWebView need App-Bound Domains (`WKAppBoundDomains` in Info.plist).
- GitHub sign-in inside WKWebView can't use passkeys; fall back to `ASWebAuthenticationSession`
  if that matters.
